# 文旅景区预订模块说明

## 1. 已完成范围

本次完成可独立联调的景区门票最小业务闭环：

1. 景区分页列表与名称、介绍、地址关键词搜索。
2. 景区详情、地址、坐标、客服电话、营业信息查询。
3. 按游玩日期查询票种、当日价格、库存和购票规则。
4. 实名游客校验及敏感信息加密保存、脱敏查询。
5. 创建订单时锁定库存，取消或超时释放库存。
6. 模拟支付后按购票数量签发电子票。
7. 工作人员核销，全部电子票核销后订单完成。
8. 未核销订单模拟退款、电子票作废并恢复库存。

暂未包含景区图文/语音导览、评价、优惠券和真实支付，这些属于后续迭代，不影响当前前后端联调。

## 2. 用户端接口

| 功能 | 方法 | 地址 |
|---|---|---|
| 景区列表与搜索 | GET | `/api/v1/app/scenic-spots?keyword=兵器&page=1&pageSize=20` |
| 景区详情 | GET | `/api/v1/app/scenic-spots/{scenicSpotId}` |
| 指定日期票种 | GET | `/api/v1/app/scenic-spots/{scenicSpotId}/tickets?serviceDate=2026-07-31` |
| 创建预订订单 | POST | `/api/v1/app/orders` |
| 模拟支付 | POST | `/api/v1/app/orders/{orderId}/mock-pay` |
| 查询电子票 | GET | `/api/v1/app/orders/{orderId}/tickets` |
| 查询脱敏游客 | GET | `/api/v1/app/scenic/orders/{orderId}/visitors` |
| 取消待支付订单 | POST | `/api/v1/app/orders/{orderId}/cancel` |
| 模拟退款 | POST | `/api/v1/app/orders/{orderId}/mock-refund` |

所有接口继续使用模拟登录返回的 `accessToken`，放入 `Authorization: Bearer ...` 请求头。

## 3. 创建景区订单示例

```json
{
  "items": [
    {
      "skuId": 123,
      "quantity": 1,
      "serviceDate": "2026-07-31",
      "timeSlot": "",
      "businessData": {
        "visitors": [
          {
            "name": "张三",
            "mobile": "13800138000",
            "idType": "ID_CARD",
            "idNo": "150204199001011234"
          }
        ]
      }
    }
  ],
  "remark": "景区门票预订"
}
```

请求必须携带唯一的 `Idempotency-Key`。实名票的 `visitors` 数量必须等于 `quantity`，游玩日期不能早于当天。

## 4. 开发数据

Flyway 的 `V9__add_scenic_booking_demo_data.sql` 会插入以下5组开发数据：

1. 北方兵器城成人票，8000分。
2. 五当召成人票，6000分。
3. 美岱召成人票，3000分。
4. 赛汗塔拉城中草原游览服务票，2000分。
5. 南海湿地景区成人票，2000分。

每个票种初始化迁移执行日起未来366天库存，每天200份。名称、票价、联系电话、坐标和图片路径均为开发联调数据，不能直接作为正式运营数据发布。

## 5. 在 IDEA 中测试

1. 保持 MySQL 和 Redis 正常运行。
2. 重新运行 `BeifanghuiBackendApplication`，Flyway 会自动执行 V9 迁移。
3. 打开 `http/api-examples.http`。
4. 依次运行第1、2、25—31步。
5. 第29步后，第30步应返回状态为 `UNUSED` 的电子票。
6. 第31步应返回已掩码的姓名、手机号和身份证号，不应出现完整敏感信息。

若应用启动前数据库已经执行过 V9，不要手工修改该迁移文件；正式数据调整应新增更高版本迁移或通过管理端完成。
